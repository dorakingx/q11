# Q11 Emergency internationalisation (EN / JA)

Module: `src/ui/i18n/` — owner of every user-visible string in the UI layer. Acceptance criterion R11 in
`docs/UX_REDESIGN.md`: EN/JA switch; short kid-friendly text first; jargon and formulas under "Details".

## Using it

```tsx
import { LanguageProvider, useT, useLanguage, plural, missionCopy, type Lang } from '../i18n';

// App root: the language is game state (Settings.language); the provider only distributes it.
<LanguageProvider language={state.settings.language}>…</LanguageProvider>

// Any component:
const t = useT();
t('city.dispatch');                                   // "Dispatch!" / "出動！"
t('title.progress', { stars: 3, max: 16 });           // "Progress: 3 of 16 stars." / "進み具合：星 3 / 16"
plural(useLanguage(), 'briefing.budget', 2);          // "2 crews" / "2 隊"   (.one / .other key pairs)

// Outside React (document.title, the aria-live announcer, tests):
import { translate, translator } from '../i18n';
translate('ja', 'doc.mission', { app: 'Q11', n: 4, title: '…' });
const tj = translator('ja');

// Browser default for a first visit (pure, testable): languageFromTag(navigator.language) → 'ja' | 'en'.
```

`t(key, params?)` fills `{name}` placeholders with strings or numbers. A placeholder with no param stays visible
(`{missing}`) so a wiring mistake shows up in screenshots and tests instead of silently disappearing. `key` is the
type `Key`, derived from the English dictionary with `as const`, so a typo is a compile error.

Mission copy (per district, both languages):

```ts
const c = missionCopy('blind-dispatch', lang);
// c.districtName, c.kidTitle, c.goal (≤ 90 chars, one sentence), c.beginnerHint, c.lessonOneLiner,
// c.reactions.{restored, safePattern, stillBurning, logicalFailure} (two short sentences, no blame),
// c.whyShort, c.detailsTitle
reactionFor(c, resultType);          // resultType from src/game/effects.ts: restored | safe-pattern | still-burning | logical-failure

// Fixture texts (fixtures/missions.json) in Japanese — faithful translations, physics exact:
fixtureCopyJa(id);                                      // { briefing, training: caption[], debrief: { success, 'logical-error', detectable } }
briefingText(id, lang, mission.briefing);               // EN passes through, JA returns the translation
trainingCaption(id, lessonIndex, lang, lesson.caption); // out-of-range index falls back to the English caption
debriefNarrative(id, debrief.verdict, lang, debrief.narrative);
```

The i18n module never imports `fixtures/missions.json` (which contains the hidden `challenge.error`): the UI already
holds the English texts through `PublicMissionView` / `Debrief` and passes them in. Secrecy (R8) is unaffected.

## Key naming

`namespace.name[.more]`, lowerCamel segments, dictionary order = screen order. Namespaces:

| Namespace | Covers |
|---|---|
| `app.*`, `doc.*` | app name, `document.title` per screen |
| `title.*` | title screen |
| `how.*` | How it works (terms + descriptions, controls, model note, the one-line quantum-rules note) |
| `city.*` | city map: HUD (stars, free roam, storage note incl. Qollab "progress lasts for one Run"), district status labels, Dispatch button, truck travel captions, restoration/badge lines, ARIA |
| `briefing.*`, `training.*` | briefing and training screens |
| `challenge.*`, `plan.*` | dispatch planning (fog, alarms, placements, Spray!, stand-down dialog, detector highlight) and the explicit plan stage (Undo / Redo / Clear / Preview) |
| `tutorial.*` | three-tap first run: "Pick a crew" → "Tap a house" → "Spray!" |
| `dispatch.*`, `spray.*` | the spray showpiece: "Training replay: answer check", skip/why/continue, captions (trucks arrive, crews running, water on, splash, extinguished / changed / ignited, remaining, alarms, done), quantum-rules and one-shot notes |
| `result.*` | result screen: headings, stars, decision/outcome/cost labels (legacy `QUALITY_LABEL` / `OUTCOME_LABEL` / `resultHeading` texts kept verbatim in EN), the four board results (`result.type.*`), the memory beacon (`result.beacon.*`), badges, "Investigation complete" |
| `why.*` | Why panel (your spray vs. the alternative, equivalence, "alarms alone cannot decide", no blame) |
| `debrief.*` | report facts, replay step titles and controls, what-if |
| `details.*` | Details fold: formulas and the stabilizer / logical / detectable definitions, "not syndrome = 0" |
| `cloud.*` | quantum verification panel; `cloud.source.*` keeps **Local (Aer) / Cached cloud result / Live cloud result** verbatim in EN and visible in JA |
| `settings.*`, `motion.*`, `notice.*` | settings (sound, reduce motion, language, free roam, storage notes, reset), reduced-motion stepper, notices (incl. save migration) |
| `summary.*`, `mission.*` | shift summary; mission labels, code names, status, star counts |
| `crew.*`, `fire.*`, `palette.*`, `alarms.*`, `legend.*` | shared labels (`crew.X` = legacy `CREW_LABEL.X`), alarm summary texts (legacy `alarmSummary`), legend incl. "Water (not a blue fire!)" |
| `a11y.*` | ARIA-only text: block/house labels, station labels, board names, announcer messages per screen (incl. `dispatch`) |
| `common.*` | OK / Cancel / Back / Close / Skip / Next / Prev / and |

Plurals: English pairs end in `.one` / `.other` (`briefing.budget`, `mission.status.attempts`, `result.costText`,
`a11y.crews`, `debrief.house`, `mission.notPlayed`); Japanese repeats the same text. Use `plural(lang, base, n)`.

## Writing rules

- **Kids first.** Short sentences, one idea each, pictures do the explaining. Jargon and formulas live under
  `details.*` and in `detailsTitle`. Never blame the player (Silent Failure is a lesson, not a mistake).
- **Science exact in every language.** Z stations (diamonds) see red X fires; X stations (squares) see blue Z fires;
  a station rings on an odd count, never on "nearby"; crews and fires combine by XOR; success = residual is a
  stabilizer (never "alarms quiet"); distance 3 fixes one fire, not two. Tests pin these sentences.
- **Keep symbols.** X / Z / Y, station ids (Z0, X1), Pauli strings (XZ, YY), formulas (X·X = I, R = C ⊕ E) and
  numbers are never translated; tests check every such token in the English fixture text appears in the Japanese.
- **Japanese style.** です・ます, polite-casual for children, EN jargon in parentheses on first use in a screen:
  警報 (alarm), 安定化子 (stabilizer), 符号 (code), 論理量子ビット (logical qubit). Fixture translations keep 街区
  (block) because they mirror `fixtures/missions.json`; kid copy says 家 (house).
- **Water ≠ blue fire.** Water is drawn and labelled as water (`legend.water`); the blue Z fire is a flame with a Z.

## Adding a language

1. Add the code to `Lang` in `core.ts` (`'en' | 'ja' | 'xx'`), to `LANGS`, `LANGUAGE_NAMES` and `isLang`.
2. Create `xx.ts` exporting `export const xx: Readonly<Record<Key, string>> = { … }` — copy `en.ts`, translate every
   value, keep every `{placeholder}` and every X/Z/Y, station id, Pauli string and formula. `tsc` fails until the
   file is complete.
3. Register it in `DICTIONARIES` in `core.ts` and add the settings key (`settings.language.xx`) in every dictionary.
4. Add `missions.xx.ts` (`Record<MissionId, MissionCopy>`) and register it in `COPY` in `missions.ts`. If the fixture
   texts should be translated too, add `fixtures.xx.ts` and extend `briefingText` / `trainingCaption` /
   `debriefNarrative` (today they are EN-or-JA; generalise `FIXTURES` to a `Record<Lang, …>` with EN passing through).
5. Extend `languageFromTag` if the browser tag should select it.
6. Tests in `i18n.test.tsx` iterate over `LANGS`, so parity, placeholders and empty-string checks cover the new
   language automatically; add the language-specific sentence counter if its punctuation differs.

## Adding a key

Add it to `en.ts` first (TypeScript then demands it in `ja.ts`), in the namespace matching the screen, with the same
`{placeholders}` in both languages. Prefer a new key over string concatenation; word order differs between EN and JA.

## Japanese pass (2026-10-11) — brand "11Q Emergency" and the glossary in force

The owner asked for natural Japanese and, because Japan's emergency number is 119, for the Japanese brand to read **11Q** (English keeps **Q11**, after 911). Every Japanese string in `ja.ts`, `missions.ja.ts` and `fixtures.ja.ts` was rewritten against its English source (です・ます for explanations and results, friendly imperatives for prompts, no English word order, few katakana), reviewed for naturalness and faithfulness, and the science kept exact. `app.lettering` (EN "Q11", JA "11Q") is what the brand mark paints on the truck; JA document titles are "11Q Emergency — …"; the title kicker / `app.tagline` is 「量子エラー訂正の消防ゲーム」. A unit test asserts that no Japanese value contains "Q11" and that every English key carrying "Q11" has "11Q" in Japanese; `e2e/japanese.spec.ts` checks the fit at 375×812 / 390×844.

Vocabulary (decide once, apply everywhere):
- brand: Q11 Emergency / Q11 ↔ 11Q Emergency / 11Q · kicker 量子エラー訂正の消防ゲーム
- fire (the Pauli token) 火 — 赤い火 (X)・青い火 (Z)・赤青の火 (Y); the incident 火事; 炎 only for the drawn flame in the mark description
- alarm station 警報ステーション (short ステーション); the alarm that rings 警報 (鳴っている / 静か); parity check パリティ検査; stabilizer check スタビライザー検査; "Z checks" Z 検査
- crews 隊 — 赤い隊 (X)・青い隊 (Z)・赤青の隊 (Y); "X crew" X 隊
- house 家 (counter 軒); city 量子の街; city map 街の地図; district 地区; fire station 消防署; fire truck 消防車
- dispatch 出動 (出動！); spray 放水 (放水！); answer check 答え合わせ; briefing 作戦説明; plan 作戦; training / lesson 訓練 / レッスン; debrief ふりかえり; result 結果; Why? なぜ？; Details 詳細; summary / shift complete まとめ / 任務完了; the call 通報 (first call はじめての通報, first dispatch はじめての出動); free roam 自由選択; hint ヒント; beginner callout はじめての人へ; badge バッジ; attempts 挑戦回数; progress 進み具合; best ベスト記録; stars 星 {n} / {max}
- memory tower 記憶の塔; memory beacon 記憶の塔のランプ; logical qubit 論理量子ビット; logical flip 反転; silent failure 静かな失敗; stored information しまってある情報
- code 符号; stabilizer スタビライザー (安定化子 given once in Details); harmless pattern 無害なパターン; residual 残った成分 (kid) / 残差 (Details, R = C ⊕ E); distance 3 距離 3; X error X エラー; Noise 放火犯「ノイズ」; bare wires むき出しの線; gate ゲート; CNOT coupler 連結器; H mirror machine 鏡の機械; S dial ダイヤル; Hadamard アダマール; control / target 制御 / 標的; odd 奇数 (explained once); chain 鎖

- style: soft kana for とじる / もどる / 切りかえる / 呼びもどす / 入れかえる / 見守る; half-width spaces around Latin letters and digits (家 4, 星 3 / 16); half-width parentheses only around Latin content, 「」/（） around Japanese; list separator 、 via `spray.list.comma`, と via `spray.list.and`.

## Not covered by this module (follow-ups for the screen owners)

- Replay captions and what-if explanations are generated in English inside `src/game/replay.ts` (`ReplayStep.caption`,
  `WhatIf.explanation`). They are derived from engine data (fires/crews/residual/syndrome on each step), so a UI can
  rebuild localised captions from the step data with `debrief.stepTitle.*`, `spray.*`, `fire.*`, `alarms.summary.*`
  and `details.*` keys; the English strings remain the authoritative fallback until then.
- `src/ui/text.ts`, `screens.tsx`, `play.tsx`, `panels.tsx`, `Scene (src/ui/scene)`, `App.tsx` still contain the English strings
  inventoried here; the migration is `t('…')` per string (every string has a key in this module).
